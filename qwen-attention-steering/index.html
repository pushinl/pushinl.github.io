02

教师怎么给监督

教师先示范：“这几段值得重点看。”

给教师的指令是：只根据当前可见历史，选出对下一步决策最重要的片段。教师输出片段编号，编号再变成 0 / 1 标签。

这个例子中，教师可以这样标
1第 1 段 · 满 100 元打九折重要
0第 2 段 · 创建分支未选
0第 3 段 · 安装成功未选
1第 4 段 · 代码写成 > 100重要
1第 5 段 · 100 元的失败测试重要
0第 6 段 · 过时猜测：100 元不打折未选

示例标签：[1, 0, 0, 1, 1, 0]

为什么选这三段？

用户要求给出正确规则：100 元也应该打折。

当前代码给出可能的错误位置：大于 100 才打折。

失败测试证明边界情况确实出了问题。

“安装成功”也是真实历史，只是这次没有提供同样直接的修复线索。

0 的意思是“这次未被教师选中”，不是断言这段内容在任何任务中都没用。

这一节记住：Prompt 用来告诉教师怎么标；学生训练时收到的是标签监督，不是把“第 1、4、5 段重要”这句话塞进聊天内容。

看标注细节：谁是教师，怎么分块，会不会切断一句话？

教师使用 Qwen3.8-Flash-Next-FP8。真实输入按原始 token 顺序切成约 256 token 的连续块，教师最多选 12 块，也允许一块不选。无效标签会有限次重试，不会凭空补造。

举例：某函数有 300 个 token，它可能横跨两个块。分块会延长截断 UTF-8 字符的边界，但没有按句子、函数做语义切分。因此连续语义仍可能跨块；未选内容也仍保留在完整输入中。这里为了易读展示的 6 段，是缩写示意，不是实际 256 token 分词结果。

教师只看当前前缀中的约束、观察、反证和未解决状态，不看后续动作、未来工具结果或评测答案。

这一节记住：评分头是经过“预测 → 对照标签 → 算误差 → 调参数”反复训练得到的。不是教师临时在线打分，也不是训练结束后凭空生成的。

看训练公式、参数与本次训练量

单块标签为 1 时，分类误差是 −log(p)；标签为 0 时是 −log(1−p)。真实训练对正负块分别求均值，再各占一半，避免大量负块淹没少量正块；全负标签也能训练。

总损失 = 动作 CE + 0.1 × 平衡的重要性 BCE

评分误差同时影响评分头和产生隐藏状态的 LoRA；有效动作的交叉熵也参与联合更新。动作目标和 padding 不进入重要性特征，因果计算保证最后一个前缀位置看不到未来动作。

本次使用指定 FP8 checkpoint 的 BF16 反量化底座训练，评分头保持 FP32。LoRA rank 32、alpha 64，覆盖 Q/K/V 与共享、路由专家。LoRA 参数 143,851,520，评分头 528,545，合计 144,380,065 个逻辑可训练参数。

16 × 910B，CP8 / DP2 / EP8，全局 batch 32（尾批 30），峰值学习率 10⁻⁵。从 checkpoint-48 恢复优化器、随机数及数据位置，累计训练至 665 步、1 epoch，21,278 个样本各曝光一次。之后合并 LoRA、导出 FP8 模型，并保留匹配的 FP32 评分头。

示例中从 0.20 换成 0.85，只是展示分数与损失的关系，不表示真实训练的一次更新就会达到该分数。

这一节记住：教师提供 0 / 1 的训练目标；学生学会输出连续分数。分数 0.96 不代表“修复成功率 96%”，也不等于 attention 权重 96%。

看评分头结构：隐藏状态怎么变成分数？

隐藏维度为 2,048。对每个历史块的隐藏状态求均值，并取当前前缀最后位置的表示；经 LayerNorm 和各自的线性投影映射到 128 维，归一化后计算余弦相似度，再乘以 4。

另一路把“块中心相对位置、距末尾的对数距离、块长度 / 256”这三个特征送入 3 → 32 → 1 的位置小网络。内容匹配结果与位置项相加，经过 sigmoid 得到分数。整个评分头有 528,545 个参数，保持 FP32。

这里的 query / key 是评分头自己的投影，不是直接取某个 Transformer attention head 的 Q / K。CP 训练按全局位置汇总块表示与最后位置，梯度可以回传；评分头也不是通过聊天 Prompt 执行任务的第二个语言模型。

06

推理时如何接起来

先找重点，再带着标记生成下一步。

上线之后，教师就不参与了。服务自己运行训练好的学生和评分头，处理每一次新的请求。

  1. 1

    完整读一遍：给历史打分

    读完同一份 6 段历史，评分头认为规则、代码和失败测试更重要。

  2. 2

    把这 3 块展开成 token 标记

    得到一组位置编号。没有把其他 3 段删掉，也没有修改用户原话。

  3. 3

    重新读同一份完整输入：开始生成

    使用新的推理状态，在指定层对标记的位置增加 attention 偏置。下一节会演示这个偏置怎么改变权重。

  4. 4

    工具返回以后，再处理下一轮

    例如模型发出运行测试的工具调用，客户端执行并回传结果。这条新结果到下一轮才进入历史，并重新评分。

这个例子里可能继续发生的工具往返 · 示意

模型请求执行测试 → 客户端执行 → 回传“测试通过” → 模型继续回答用户。

是否真的会选对工具、写对修改，需要实际评测；上述对话是流程示意。

这一节记住：这版有“评分”和“生成”两次完整处理。只用训练后的模型权重做普通推理，不会自动多出这次评分和显式 attention 偏置。

看工程实现：为什么有两次完整前向？

评分阶段做完整 prefill，取得因果隐藏状态并运行匹配的 FP32 重要性头；随后使用完全一致的完整 input IDs，重新创建 KV / GDN 状态做生成 prefill。两阶段核对输入 token 哈希，不复用评分阶段的状态。每个新决策请求重新评分。

本实现为了正确性关闭 CUDA graph、radix cache、chunked prefill 和调度重叠；仍使用原生 FP8 与 CUDA 算子。两次 prefill 和查询行重算会增加开销，不能把这套 steering 当作推理加速技术。历史部署为每 GPU 一个执行请求，8 个独立副本可同时执行 8 个请求。

07

最终怎样影响 attention

给重要位置加一点分，再重新分配注意力。

生成下一个 token 时，attention 会决定如何综合历史信息。我们在原本的匹配分数上，给选中位置加一个偏置，然后让所有位置重新归一化。

先算一个很小的例子

4 个位置原本各占 25%，只增强其中一个。

假设选中“失败测试”对应的位置，偏置强度设为 1。它的相对权重被放大约 2.72 倍；重新归一化后，它从 25.0% 变成 47.5%，其他三个各约 17.5%。

这是便于手算的独立示意：4 个位置、1 个被选中，并不是前面 6 块历史的实测 attention。真实服务会同时增强所有选中块中的 token。

点选位置、拖动强度，看权重怎样重新分配。

绿色 = 被选中的历史位置

λ = 0 就是没有偏置；本版默认 λ = 1。

2.72×相对未选位置，未归一化权重放大的倍数

原来加入偏置后
被选位置的注意力合计25.0%→47.5%

最关键的一步：权重改了，为什么输出也可能改变？

因为 attention 读回来的，是历史信息的“加权汇总”。

不是直接给未来的 >= 加分，而是先改变模型从历史里读回来的信息。

  1. ① 改变参考比例

    测试位置的 attention 从 25% 变成 47.5%，过时猜测的位置从 25% 变成 17.5%。

  2. ② 改变汇总后的表示

    每个历史位置带有一组信息数字，叫 V。模型把各位置的 V 乘以对应 attention 权重，再相加。权重一变，加权结果也变。

  3. ③ 影响后续计算

    汇总结果经过输出投影、残差连接、后续层等计算，影响最后用于预测的隐藏状态。

  4. ④ 改变下一个 token 的概率

    最后的输出层根据隐藏状态给整个词表打分。分数变化后，采样到不同 token 的机会也会变化，生成内容可能随之改变。

跟上面的控件联动 · 一个两维玩具模型

把“历史信息 → 输出概率”也算出来。

人为设定：测试位置的 V = [1, 0]，过时猜测位置的 V = [0, 1]，另外两个位置为 [0, 0]。把第一个维度暂称为“支持 >=”，第二个称为“支持 >”。

真实 V 是训练出的向量，维度没有这种预先写好的语义。下面的 V、后续映射和概率都是教学设定，不是 Qwen 的测量结果或收益预测。

计算传到哪一步没有偏置按当前选区和强度
测试 / 旧猜测的 attention25.0% / 25.0%47.5% / 17.5%
读回的信息 = Σ attention × V[0.250, 0.250][0.475, 0.175]
简化后续网络：两个维度各乘 4[1.000, 1.000][1.901, 0.700]
只在 >= 与 > 两个候选中，选 >= 的概率50.0%76.9%

这里假设两种符号各是一个候选 token，并只在二者之间归一化；真实模型面对完整词表与连续多步生成，分词也可能不同。“乘 4”是为看清过程而设置的固定映射，代替了复杂的后续网络。

所以，为什么可能改善表现？又为什么可能变差？

如果评分头找到了被长历史淹没的关键约束，偏置有机会让这些信息更多地进入后续计算，帮助模型生成合适的下一步。若选中了误导信息，也可能把计算推向错误方向。即使选对位置，其他 attention heads、残差和后续层仍会影响输出，不能保证修复成功。

“选中信息的相对 attention 增大”是计算规则；“任务成功率提高”是需要对照评测的结果。

评分头负责“选谁”

前面“失败测试”的重要性得分是 0.96，所以它超过门槛，进入选区。

偏置强度负责“增强多少”

实际加入 attention 匹配分数的是固定的 λ = 1，不是把 0.96 当权重，也不是把它直接加进去。

这一节记住：重要性分数决定标记哪些位置，偏置再改变这些位置的相对注意力。所有位置仍参与计算，也不保证最终一定修对代码。

看公式与边界情况：为什么 25% 会变成 47.5%？
z′j = zj + λ · mj；a′ = softmax(z′)

z 是原始 QK 匹配分数（含缩放和原有掩码），m 是选区的 0 / 1 标记。未选位置保持原分数。softmax 先取指数，再除以所有位置的总和，保证权重加起来仍然是 100%。

例子中原始分数全为 0，未归一化权重原本都是 1。给一个位置加 1 后，它变成 e¹ ≈ 2.718；新权重为 2.718 / (1 + 1 + 1 + 2.718) ≈ 47.5%。

若选区原本注意力合计为 r，固定 Q/K 后的新合计为 r′ = e^λ r / (1 − r + e^λ r)。λ = 0、全选、全不选时分布不变。重要性分数不是经过校准的 attention 概率。

看作用位置：为什么是第 27、31、35、39 层？

可以把模型的 40 层理解为逐步加工信息的 40 道工序。这版预先选定最后四个 full attention 层，在这些层的所有 attention heads 上，对最后一个前缀查询及后续生成查询施加偏置。较早历史查询行不接受本次修正。

绿色边框为本版的固定干预层。层号从 0 开始。

每 4 层是 3 层 linear attention（Gated DeltaNet）加 1 层 full attention。Full attention 有面向历史位置的显式 QK 分数，可以逐位置加偏置；linear attention 通过递归状态汇总历史，不能直接套用同一方法。27 / 31 / 35 / 39 是固定原型选择，没有证明是最佳层。

当前运行路径先执行原生 attention，再用该层的实际 KV 槽重算需要干预的查询行，FP32 softmax 后写回修正输出；因果可见性不变。

额外加到被选位置匹配分数上的数值，用于改变相对注意力。
