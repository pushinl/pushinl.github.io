两个“256”，含义不同

当前实现

当前的 256 是历史分块的长度。例如 1,024 个历史 token 可形成约 4 块，在请求开始时同一轮评分；不会因此调用评分头 4 次。图中的“第 256 个”指新生成 token，当前实现经过它时不重评。实际边界为约 256 token，可能为了完整解码略作延长。

为什么新请求要重新评分？

旧历史 A–D＋新工具结果 E→新的请求末尾→重新比较 A–E

评分头会把当前请求末尾的表示与每个历史块比较。工具结果进来后，当前要处理的问题变了；所以即使 A–D 的文字没变，它们相对于“现在要做什么”的分数也可能改变。图中 C 从 0.77 变为 0.44，D 从 0.69 变为 0.90，就是这种变化的示意。

服务可以缓存旧前缀的部分计算，但那不等于沿用旧分数。只有 Agent 带着更新后的历史再次发起模型请求，评分头才重新运行；单次回复中逐 token 计算的 attention 仍会持续变化。
