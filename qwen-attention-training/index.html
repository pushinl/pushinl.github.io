本轮方法：教师重要性监督的 LoRA 微调。当前模型尚未在推理时显式使用重要性分数调整 attention。

01 / The whole picture

从一段历史，到一组新权重

先把全流程串起来：教师负责给出重点，学生同时学习动作与重要性，两个目标共同参与训练。

1数据准备

保留完整决策历史

把采集到的轨迹拆成“当前可见历史＋已有的下一步动作”。每条样本保留完整历史前缀。

2教师标注

选择重要片段

历史按约 256 tokens 分块。教师最多选 12 块：选中记为 1，其余记为 0。

3学生前向

同一学生，两项预测

一条分支预测下一步动作；另一条分支用小打分器预测各历史片段的重要性。

4联合训练

误差回传，共同更新

动作误差＋0.1 × 重要性误差。反向传播更新学生 LoRA，重要性误差还更新打分器。

5模型交付

合并权重，正常推理

将 LoRA 合入学生并导出 FP8。评测直接运行新权重，教师与打分器不参与普通推理。

→
重点在第 4 步：教师的标注通过“重要性误差 → 反向传播 → 学生 LoRA”这条路径影响学生。
教师的 0/1 标注用于计算训练误差；不会作为提示词或 attention 权重直接交给学生。

教师能看到什么？

只看到本次决策前已存在的历史。下一步动作、未来工具结果、测试结果和正确补丁都不会提供给教师。

动作的标准答案来自哪里？

来自已采集的 Agent 轨迹。教师只补充“哪里重要”的标签。本轮没有让教师重新生成下一步动作答案。

03 / How labels change the student

为什么只标重点，也能改到学生？

打分器使用学生产生的内部表示。分数算错后，误差沿这条连接回传，因此两部分都能被更新。

学生 / 动作重要性监督训练误差

前向计算：同一份学生内部表示，同时用于生成动作和预测重要性。教师标签只在“重要性误差”处与学生分数比较。

实际训练目标 · 省略分布式归一化系数
总误差 =动作误差+0.1×重要性误差

重要性监督开启：额外误差可以影响学生 LoRA，也训练打分器。这是本轮实际使用的设置。

01改学生的哪一部分？10 个完整 attention 层的 Q/K/V/O 相关 LoRA，以及专家层 LoRA。原始基础权重冻结。
02为什么不是只改打分器？内部表示与打分器之间保留了梯度连接。重要性误差能继续回传到产生这些表示的学生参数。
03是否强制 attention 更集中？没有。目标是让内部表示更容易识别重要片段，尚未直接约束 attention 分布。

不使用打分器，训练效果为什么还在？

打分器是训练期间产生辅助监督的分支。其误差已经修改了共享的学生 LoRA；合并后，参数变化仍参与每次正常生成。

能直接声称模型更关注重点了吗？

目前可以确认监督信号进入了训练。尚不能确认任务效果已提升，也不能确认重要片段获得了更大的 attention 权重。

技术细节：重要性分数与误差是怎样算出来的？

取每个历史块内 token 的学生隐藏状态均值作为块表示，以当前可见历史的最后一个 token 表示作为查询。额外打分器对两者分别投影，计算相似度，并加入位置特征得到 logit；通过 sigmoid 可展示成 0～1 分数。

教师返回选中的块 ID。代码将选中转换为 1、其余转换为 0，用 binary_cross_entropy_with_logits 计算逐块损失。正负块同时存在时，各占一半权重，避免大量未选中块淹没正例。若全为一类，则取平均损失。

目标 y = [1, 0, 1]
学生示意概率 p = [0.20, 0.80, 0.30]
正例平均误差 = (−ln(0.20) − ln(0.30)) / 2
负例平均误差 = −ln(1 − 0.80)
重要性误差 = 0.5 × (正例平均误差 + 负例平均误差) ≈ 1.5081
核心目标：L = L_action + 0.1 × L_importance

实现中还有有效样本与分布式并行的归一化。训练损失没有切断通向学生隐藏状态的梯度；日志统计使用的 detach() 不影响训练路径。

技术细节：LoRA 实际修改了哪些部分？

冻结原始基础参数，在 40 层中的 10 个完整 attention 层上训练 Q/K/V/O 对应的 LoRA；同时训练各层共享专家和路由专家的 LoRA。attention / 共享专家使用 rank 32、alpha 64；路由专家使用共享外层因子的 rank 8、alpha 16。GDN、路由器及视觉部分保持冻结。

逻辑可训练 LoRA 参数为 143,851,520；额外 FP32 打分器为 528,545；共计 144,380,065。合并导出把 LoRA 的增量加进学生权重，独立保存打分器。当前没有教师 attention 矩阵蒸馏或显式 attention 分布损失。

交付审计：导出副本选择与验证范围

原始跨数据副本一致性检查没有通过。当前交付采用 DP0 内部一致的 8 个专家分片导出，保留了历史失败记录；这不代表已解决跨副本差异。所选副本到 LoRA 导出的投影校验通过。

BF16 合并模型已通过实际加载与短生成检查。FP8 交付已完成张量、权重哈希、格式和重构检查；尚未完成该模型的原生 SGLang / TRPC 服务验证、完整上下文压力测试或独立 Agent 效果评测。
